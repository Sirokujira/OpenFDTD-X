# ADR-0014: 音源の指向性の契約 (acoustic.feeds[].directivity / aim)

## Status

Accepted (2026-10-31) — ソルバー側 (OpenAcoustics の `ofdx_acoustic_fdtd` /
`ofdx_acoustic_ga` 両バイナリ) は実装・検証済み (OpenAcoustics PR #9)。
GUI 側も実装済み: AcousticSolverTab の feed 表の「指向性」「向き」列 →
`AcousticOpts::FeedDrive` (directivity / aim) → `.ofdx` `acoustic.feeds`。
無指向のままならキーを書かない (絶対規則 2)。起動前点検
(`AcousticPreflight`) が向きの無い指向性と未知の名前を止める。selftest
`dir-ofdx:` / `preflight:` が往復・保持・バイト一致を検証する。
音源リスト (AcousticSourceTab) の種類・向きからの自動反映は範囲外
(Consequences)。

## Context

- 外部ソルバーの音源 (`.ofd` の feed) はこれまで**全て無指向**だった
  (ADR-0010 Consequences)。舞台上の歌手・スピーカーは前方に強く、
  後方に弱いので、無指向のままでは客席の直接音と初期反射のバランスが
  変わる。
- 指向性は**両ソルバーで同じ**でなければならない。ハイブリッド合成
  (ADR-0008) のクロスオーバーは、低域 (FDTD) と高域 (幾何音響) が同じ
  音源から同じ方向へ同じ強さで出ている前提で帯域エネルギーを継ぐ
  (ADR-0010 / ADR-0011 / ADR-0012 と同じ理由)。
- FDTD は波動方程式を解くので、任意の指向性を入れるには音源の多重極
  展開が要る。1 次 (単極 + 双極子) までなら点音源 1 セルで厳密に作れ、
  無指向〜カーディオイド〜8 の字の実用的な範囲を覆う。

## Decision

1. **指向性は 1 次の軸対称パターン** D(θ) = a + (1−a) cosθ とする。
   θ は向き (aim) からの角度。**軸上 D(0) = 1 に規格化**する (軸上の音圧は
   同じゲインの無指向音源と同じ — 指向性を変えても軸上のレベルは動かない)。
   a < 0.5 の背面ローブは D < 0 = **極性反転** (物理どおり。8 の字の背面は
   逆相)。
2. **`.ofdx` の `acoustic.feeds[i]` に `directivity` と `aim` を足す**
   (ADR-0010 Decision 7 の行に追加キー。`acoustic` 直下なので両ソルバーが
   読む):
   ```json
   "acoustic": {
     "feeds": [
       { "gain": 1, "delay_s": 0, "directivity": "cardioid", "aim": [0, -1, 0] },
       { "directivity": [1, 1, 0.5, 0.5, 0.25, 0.25], "aim": [1, 0, 0] }
     ]
   }
   ```
   - `directivity` は次のどれか:
     - 名前: `omni` (a = 1) / `subcardioid` (0.7) / `cardioid` (0.5) /
       `supercardioid` ((√3−1)/2 = 0.366) / `hypercardioid` (0.25) /
       `figure8` (0)
     - 数値 a (0〜1)
     - バンド別の配列 (125 Hz〜4 kHz の最大 6 値。足りないバンドと幾何音響の
       8 kHz は最後の値で外挿 — 吸音表と同じ規則)
   - `aim` = `[x, y, z]` は音源が向く方向。長さは無関係 (ソルバーが正規化)。
   - **無指向 (キー省略・`omni`・全バンド 1) は従来動作とビット単位で一致**
     (aim は読み飛ばされる)。
   - 次は**非零終了** (無指向に落とさない — 数値を捏造しない):
     a < 1 のバンドがあるのに aim が無い / 0 ベクトル、未知の名前、
     範囲外の a、3 要素でない aim。ソルバーは発火しない feed
     (multi_source オフの #2 以降) の指定も検査する。
3. **両ソルバーの意味**:
   - FDTD — ソフト音源 (単極) を a 倍し、音源セルの各軸 2 面の粒子速度に
     **力の双極子** (1−a) n s(t)/(2ρc) を足す。遠方の軸上で単極と双極子の
     振幅が一致する規格化で、双極子の近接場 (1/(ikr) 項) も波動方程式どおり
     持つ。a は**有効帯域内のバンド平均** (吸音率と同じ規則 — 低域担当が
     高域の指向性を混ぜない)。
   - 幾何音響 — 直接音と鏡像の振幅に放射方向の D_b (鏡像は経路の最初の
     区間の方向)、レイのエネルギーに発射方向の D_b² (バンド別)。総放射
     パワーは D² の球面平均 a² + (1−a)²/3 倍 (カーディオイドで 1/3) に
     なり、残響のレベルはこれに従う。
4. **metadata.json は追加キーのみ**: `sources[]` の各要素に、FDTD は
   `directivity_a` (実効 a、無指向は 1) と `aim` (正規化後、無指向は
   [0, 0, 0])、幾何音響は `directivity` (7 バンドの a) と `aim`。
   ファイル契約 (ADR-0007) は不変。
5. **GUI** (AcousticSolverTab の feed 表):
   - 「指向性」列は 6 つの名前から選ぶ。手書きの数値・バンド別の配列は
     「ファイルの値」と表示し、利用者が別の項目を選ぶまでそのまま書き戻す
     (表示専用 — 選べない)。数値はクランプして読み、名前はそのまま持つ
     (未知の名前を別の指向性に置き換えない — 起動前点検が止める)。
   - 「向き」列は x, y, z。無指向から切り替えたとき向きが 0 なら +X を
     入れる (見える形で入れるので直せる)。無指向に戻すと向きも消し、
     行が既定に戻る (旧ファイルとバイト一致)。
   - 各行の他のキー (手書きの未知キー、3 要素でない aim) はそのまま書き
     戻す。以前は `{gain, delay_s}` だけを書き戻していたので、手書きの
     `directivity` は GUI でゲインを変えた時点で黙って消えていた。
6. **ソルバー側の番人** (OpenAcoustics `acoustic_check.sh`):
   - FDTD (s) — 点モノポール + 点力双極子の閉形式
     |a + (1−a) cosθ (1 + 1/(ikr))|/r と 6 方向の振幅比 (最大差 0.01、
     kr = π で近接場項を含む)。8 の字の斜め向き、帯域内が 125 Hz だけに
     なるバンド配列 (= カーディオイド、長さ 2 の aim)、無指向の明示の
     ビット一致、指向性つき 2 音源の重ね合わせ、異常系 4 種。
   - 幾何音響 (M) — バンド中心 DFT の符号つき D_b (125 Hz 無指向 /
     1 kHz カーディオイド / 4 kHz 8 の字 / 8 kHz 外挿、最大差 0.01)、
     無損失室の後期エネルギー比 = D² の球面平均 (±3%)、音源ごとの
     対応づけ、無指向の明示のビット一致、異常系 4 種。

## Consequences

- (+) 既存フローは無変更 (opt-in、キー省略時は従来動作と完全一致)。
  ADR-0003 の未知キー無視により、旧版 GUI / 旧版ソルバーとも共存できる
  (旧版ソルバーは無指向として動く — 指向性が効かないことに注意)。
- (+) 表 1 つで両ソルバーに同時に効く (単発実行・ハイブリッド実行とも同じ
  `prepareRunInput` 経路でサイドカーを書く)。
- (−) 1 次 (単極 + 双極子) まで。実測の指向性データ (バルーン)、2 次以上の
  多重極、非軸対称のパターンは扱わない。
- (−) 音源リスト (AcousticSourceTab — `kind` / `aim`) からの自動反映は
  しない (「⚡ ソルバ波源へ反映」は従来どおり位置のみ)。種類の
  Bipolar / Directional は 1 次パターンで表せず、向きの表記 (`-Z 30°` 等)
  の書式も決まっていないため。反映するなら別 ADR で表記を決める。
- (−) FDTD の a は有効帯域内の 1 値 (帯域内で周波数依存の指向性は
  範囲外 — 吸音率と同じ制約)。
