# .ofd / .ofdx 互換性の規則

## .ofd (カーネル入力テキスト)

- 新キーの**書き出しは機能有効時のみ**。無効時の出力は従来と
  バイト一致でなければならない (selftest にバイト一致チェックを追加)。
- パーサで認識するキーは `extraLines` に退避しない
  (退避すると再保存時に二重出力される)。
- GUI が扱わない未知キーは `extraLines` で逐語保全する (round-trip)。
- キーのフォーマットはカーネル側 (`OpenFDTD/sol/input_data.c` 等) の
  パーサ仕様が正。GUI 側で勝手に単位や引数順を変えない。

## .ofdx (JSON sidecar)

- **追加キーのみ**。既存キーの改名・削除・型変更・順序変更は禁止。
- 読み込みは欠落キーを既定値で埋める (旧ファイル互換)。
  `value(...).toDouble(既定値)` パターンを踏襲する。
- schemaVersion は**互換性を壊すために上げるのではなく、内容の目印**として使う。
  現在の定義は `acoustic.opera_analysis` を含めば "1.1"、含まなければ "1.0"
  (`docs/opera-acoustics-file-format.md` §1)。`OfdxIO::serialize` は固定値では
  なく**実際に書いた中身**から決める。**読み手は版で分岐しない** (キーの有無で
  判定する) ので、古い読み手が新しい版のファイルを読んでも壊れない。
  この不変条件は selftest の `ofdx-schema` が検査する。
- 新キーを追加したら selftest に (a) ラウンドトリップ、
  (b) 旧ファイル読み込みで既定値になること、の両方を追加する。

## Project 構造体

- フィールド追加時は既定値をメンバ初期化子で与える
  (シリアライズ前の未初期化状態を作らない)。
- 単位はフィールド名に含める (`_um`, `_nm`, `_W`, `_cmGW` 等の接尾辞)。
